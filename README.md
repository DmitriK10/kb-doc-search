# KB — ИИ-агент поиска ответов по корпоративным документам

MVP без LLM-генерации: агент находит релевантный фрагмент и показывает его
**дословно** со ссылкой на документ и раздел. Если надёжного фрагмента нет —
честный отказ. Галлюцинация исключена архитектурно, а не промптом.

## Статус: что проверено, а что нет

Принцип проекта: **цифра существует, только если её воспроизводит команда.**
Поэтому ниже — не «сделано», а «проверено на живой системе».

| Чанкинг по пунктам | проверено | `app/ingest/chunker.py`: 9 чанков, склейка 3.1–3.4, раздел и пункт разведены в `embed_text` |

проверены полностью, а непроверенным остаётся только доступ к pgvector.

## Порядок миграций

Имена файлов не совпадают с порядком применения — это осознанно:

```
000_extensions.sql   расширения (vector, pg_trgm, btree_gist, pgcrypto)
002_lexeme.sql       kb_norm, kb_lemma, kb_lemmas, kb_tsv, агрегаты tsquery
003_synonyms.sql     term_synonyms + kb_expand_query + kb_tsquery
001_schema.sql       документы, чанки, журнал, кластеры (зависит от kb_tsv)
```

`001_schema.sql` грузится последним, потому что использует `kb_tsv()`
из `002`. Если применить его раньше — PostgreSQL упадёт на неизвестной
функции в generated-колонке.

## Решения, которые нельзя менять не подумав

1. **`doc_key` без версии.** `reg_dogovora_v2.3` и `reg_dogovora_v3.1` — один
   `doc_key = reg_dogovora`. Иначе фильтр актуальности не работает, и вся
   борьба с «устаревшими регламентами» обнуляется.

2. **`chunks.is_active` денормализован.** Фильтр актуальности нельзя делать
   через `JOIN` с `documents` внутри `ORDER BY embedding <=>` — это убивает
   HNSW (3 мс → 40 мс).

3. **ё/е: замена только симметрично.** Словарь `russian` уже унифицирует
   ё/е (проверено: `tsv('Отчёт') == tsv('Отчет')` → `true`). Ручная замена
   в одном месте создаёт асимметрию и ломает поиск. Из токенизатора она
   убрана; в `kb_norm` оставлена для не-словарных путей и применяется к обеим
   сторонам.

4. **Синонимы матчатся по лексеме.** Ключ `term_synonyms.term_lemma`
   считается тем же `kb_lemma`, что и токен запроса. Поверхностное сравнение
   молча не находило падежные формы.

5. **Версии не идут в полнотекст.** `2.3` в AND-цепочке обнуляет выдачу
   (в `tsv` версий нет). Версия уходит в структурный фильтр
   `documents.version` и в stale-флоу (`app/search/versions.py`).

6. **Потолок 8 AND-групп.** По 40 группам совпадений не бывает: развёрнутый
   вопрос даёт 10+, и FTS-ветка молча умирает, оставляя RRF с одной веткой.

7. **Кэш включает ACL.** `cache_key = HMAC(pepper, query | acl_signature)`.
   Иначе сотрудник без прав получит зарплатное положение из кэша HR.

8. **`response_type='stale'`** — третье значение, не «успех». Deflection =
   `(success + stale) / total`, Stale Rate показывается отдельной строкой.

## Запуск проверок

```powershell
# SQL: функции, лексемы, tsquery, поиск (нужен PostgreSQL, pgvector не нужен)
python scripts/smoke_db.py --dsn "host=127.0.0.1 port=5432 user=postgres password=... " --mode fts

# Схема: ограничения, версионность, дедупликация (pgvector подменяется на TEXT)
python scripts/test_schema.py --dsn "..."

# Чистая логика: RRF, реранк, признаки уверенности (без БД)
python tests/test_fusion.py
```

Отчёты пишутся в `reports/*.json` — их и надо прикладывать к презентации,
чтобы каждая цифра со слайда воспроизводилась командой.

## Ограничения среды разработки

- **pgvector не установлен**: установка требует прав администратора
  (`C:\Program Files\PostgreSQL\18\share\extension`). Проверка `halfvec`,
  `<=>` и HNSW переносится на KVM-сервер, где pgvector ставится из PGDG.
- **torch/transformers не установлены**: ONNX int8 для rubert-tiny2
  экспортируется в отдельном dev-venv; в прод едет только `onnxruntime`.
  В репозитории модели на HuggingFace ONNX-файла нет — только safetensors,
  поэтому экспорт обязателен, а не опционален.
